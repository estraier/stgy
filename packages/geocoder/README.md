# stgy-geocoder

Node.js用の静的ジオコーダーです。地名レコードはオブジェクトとして保持し、補助点はロード後に`Float32Array`と`Uint16Array`または`Uint32Array`へ格納します。

## 使用例

```ts
import { GeoCoder } from "stgy-geocoder";

const geoCoder = new GeoCoder(["packages/geocoder/data/geo-japan.ndjson"]);

console.log(geoCoder.encode("Tokorozawa"));
console.log(geoCoder.encode("所沢", "ja"));
console.log(geoCoder.encode("Tsurumi ward", "ja"));
console.log(geoCoder.decode(139.4689, 35.7994));
console.log(geoCoder.decode(139.4689, 35.7994, "ja"));
```

デフォルトロケールは`Config.DEFAULT_LOCALE`で指定し、現在は`en`です。ロード時に全住所レコードの`locale`を調べ、一つ以上の住所が存在するロケールをサポート対象とします。ロケールは`ja_JP`を`ja-JP`へ変換するなど正規化し、まず完全一致を探し、なければ`ja-JP`から`ja`のように基本言語を探します。どちらもサポートされていない場合や引数を省略した場合はデフォルトロケールとして扱います。

返却される各場所の`addresses`には常に英語住所を含めます。英語以外のサポート対象ロケールを指定した場合は、その場所に該当住所があれば英語住所に続けて追加します。それ以外のロケールは返しません。生成時に英語名を対応付けられなかった場所では、存在する住所だけを返します。

`encode`の検索索引はロケールごとに分離されています。解決されたロケールが英語以外なら、そのロケールと英語の両方の索引を検索します。そのため、`locale="ja"`でも日本語名と英語名のどちらで検索しても一致します。検索キーは大文字・小文字を区別しません。また、完全住所に加えて、`日本埼玉県所沢市`から`埼玉県所沢市`、`所沢市`を作るように、`elements`の先頭階層を順に省略した住所も索引へ登録します。英語でも`Tokorozawa, Saitama, Japan`、`Tokorozawa, Saitama`、`Tokorozawa`を検索できます。完全ラベルを別名より優先し、同じ別名が複数の場所にある場合は一致した場所をすべて返します。一致した各場所について日本語住所の`elements`から階層を復元し、重複を除いたうえでレベル降順・ID昇順の安定した順序で返します。

## levelとkind

`level`は国を第1階層とする地理階層の深さです。`kind`は国ごとに異なる行政単位の意味を表します。各住所レコードの`elements`には国からその場所までの完全な階層を格納するため、レコード単体の`label`でも世界規模の場所を表せます。国レコード自体も別の階層として返します。

| level | kind | 例 |
| --- | --- | --- |
| 1 | `country` | 日本 / Japan |
| 2 | `prefecture` | 日本神奈川県 / Kanagawa, Japan |
| 3 | `municipality` | 日本神奈川県横浜市 / Yokohama, Kanagawa, Japan |
| 3 | `special-ward` | 日本東京都世田谷区 / Setagaya, Tokyo, Japan |
| 4 | `designated-city-ward` | 日本神奈川県横浜市鶴見区 / Tsurumi, Yokohama, Kanagawa, Japan |

日本の国レコードにはISO 3166-1 numericの392をIDとして使い、代表点には東京都港区麻布台の日本経緯度原点を使います。

政令指定都市の行政区は市とは別の検索レコードとして収録します。ただし逆ジオコーディングでは、市全体の代表点・補助点を候補にせず、各行政区の代表点・補助点を使用します。東京都の特別区と通常の市町村は従来どおり逆ジオコーディング候補です。

`decode`は上記の逆ジオコーディング候補の代表点と補助点を読み込み後に緯度順へ並べ替えます。検索時は緯度が南北10 km以内にある範囲を二分探索で切り出し、その候補だけを走査します。最近傍点が10 kmより遠い場合は空配列を返します。NDJSON内のレコード順には依存しません。

## データ生成

```sh
npm run generate:japan --workspace packages/geocoder
```

このコマンドは次を行います。

1. Python仮想環境を`packages/geocoder/.cache/`へ作成する。
2. 必要なPythonパッケージを導入する。
3. N03 2026年版の原本を`source-data/N03-2026/`へ取得する。
4. デジタル庁アドレス・ベース・レジストリの市区町村マスターを公開カタログから取得する。APIキーは不要。
5. 日本経緯度原点を代表点とする日本の国レコードを生成する。
6. `N03_004`から市町村・東京都特別区を、`N03_005`から政令指定都市の行政区を生成する。
7. 政令指定都市については区ポリゴンを合成して市のレコードも生成する。
8. 日本語・英語の各住所へ国から対象場所までの完全な`elements`を設定する。
9. N03とABRの日本語名称を照合し、対応できた場所へ英語住所を追加する。対応できなかった場所は日本語住所だけを残し、警告を出力する。
10. 通常の市町村・東京都特別区・政令指定都市の行政区に、2 km間隔の補助点と0.25 km²以上の未収録構成面の補完点を生成する。
11. `data/geo-japan.ndjson`を書き出す。
12. 1 km検証グリッドで最近傍判定を検証する。
